# AGENTS.md: ZhirGram (патчсет поверх Telegram для Android)

Для агента, который продолжает работу. Прочитай целиком до первой правки.

## Что это

Собственный Android-клиент Telegram. Владелец пишет по-русски: отвечай по-русски, коротко, без воды и
без длинных вступлений. Он работает с телефона (Termux), поэтому **вся сборка идёт в GitHub Actions**,
локальной сборки нет.

История: сначала начали клиент на Compose + TDLib (репозиторий `zhirgram`, остался как заготовка). Владелец
захотел полноценный клиент сразу, поэтому выбрана схема «патчи на стоковый Telegram», как у MargyGram и
Inugram. За основу взят **Inugram** (MIT, `teidesu/inugram`): его патчи, скрипты и инфраструктура.
Подробнее о схеме: `docs/inugram-agent-guide.md` (руководство автора Inugram, читать как справку; его
запреты вроде «не запускай git» относятся к его рабочему процессу, а не к нашему).

Структура: `upstream-commit` (коммит DrKLO/Telegram), `series` (порядок патчей), `patches/<группа>/*.patch`,
`src/fork` (наш Kotlin-код, линкуется в worktree), `src/res`, `scripts/` (setup на TypeScript),
`patches-native/` (патчи сабмодулей). В CI `pnpm run setup -- --ci --pluginless` клонирует Telegram и
накладывает патчи через `git apply --index`.

## Главное: чужая идентичность в патчах (сделать в первую очередь)

Inugram зашил в патчи данные автора. Их нельзя оставлять в нашем приложении:

1. **api_id и api_hash.** В `patches/misc/build-support.patch` стоят заглушки (`APP_ID = 0`, пустой hash).
   CI подставляет значения владельца из Secrets `TG_APP_ID` и `TG_APP_HASH` (шаг в `build.yml`).
   Никогда не коммить настоящие значения. Проверка: `grep -rn "APP_HASH" patches` не должен находить 32-символьный hash.
2. **Идентификатор приложения.** Заменён на `com.qwenz.zhirgram` (там же). Kotlin-пакет `desu.inugram.*` оставлен
   намеренно: переименовывать сотни файлов не нужно, идентификатор приложения от него не зависит.
3. **Firebase.** В `TMessagesProj/google-services.json` и `TMessagesProj_App/google-services.json` (через патч)
   лежит Firebase-проект автора Inugram (`inugram-5dcad`). Мы лишь сменили `package_name`, чтобы плагин не падал.
   Это временно. Нужно либо завести свой Firebase-проект и заменить json, либо отключить плагин и FCM
   (тогда пуши в закрытом приложении не приходят). Решение согласовать с владельцем.
4. **Обновления.** `src/fork/helpers/update/UpdateHelper.kt` смотрит на каналы и релизы Inugram. До замены на
   свои релизы обновление отключить, иначе приложение предложит чужой APK.
5. **Ссылки и бренд.** `AboutActivity.kt` ведёт на GitHub и канал Inugram; в `branding.patch` строки «Inugram»,
   иконки, тип системного аккаунта `desu.inugram` (`auth.xml`, `sync_contacts.xml`). Заменить на свои:
   `grep -rIn "inugram" src patches --include=*.kt --include=*.patch | less`.
6. **Облачная синхронизация настроек, отчёты о падениях** и подобное: проверить, куда отправляются данные.

## Как писать патчи (важно)

У агента нет исходников Telegram под рукой. **Патч без точного контекста строк не применится.**
Способы:
- Свой код кладёшь в `src/fork` (файлы целиком, контекст не нужен) и подключаешь через уже существующие
  хуки (`patches/hooks/*`) или через маленький патч.
- Чтобы увидеть настоящий файл с уже наложенными патчами, запусти workflow **Export stock files**
  (Actions, поле `paths`), скачай `files.zip` и работай по нему. Это ~5 минут, дешевле полной сборки.
- Новый патч: файл `patches/<группа>/<имя>.patch` (группы `bugfix`, `feature`, `debloat`, `hooks`, `misc`), строка
  в конец `series`. Формат: unified diff, применяется `git apply --index`. Меняя только добавленные
  строки существующего патча, не трогай счётчики `@@`.
- Проверка, что патч применяется: Export stock files (setup накладывает всю серию и падает на конфликте).
- Не правь `TLRPC.java`, схему БД стока и `LAST_DB_VERSION` (правило Inugram, оно разумное).
- Новое поведение прячь за настройкой `InuConfig`: по умолчанию должно вести себя как сток.

## Дизайн-цели владельца

- **Настоящий Material 3 и Material 3 Expressive**, а не россыпь декоративных форм. Expressive это в первую
  очередь пружинное движение, читаемая иерархия, заметный главный action, формы с причиной. Ошибка первой
  заготовки: аватары чатов в «печеньках» и «звёздах» по всему списку, это шум (в скиллах прямо сказано, что
  `MaterialShapes` нельзя в плотных списках). Не повторять.
- Пружинные анимации (spatial с отскоком только для движения, размера и формы; цвет и прозрачность без отскока).
- Переключатель «классический интерфейс»: в Inugram уже есть похожее (`feature/non-island-ui.patch`, режимы
  классического UI). Посмотри их до того, как писать своё.
- В стоковом Telegram экраны на самописных View, не на Compose. Свои новые экраны можно делать на Compose
  через `ComposeView` внутри `BaseFragment`, но для этого нужно добавить Compose в Gradle-модуль Telegram
  (плагин компилятора Compose и зависимости). Это отдельная задача, сначала согласуй с владельцем и проверь,
  какая версия AGP и Kotlin в стоковом проекте.
- Скиллы `.claude/skills/material-3` и `.claude/skills/material-3-expressive`: читай `SKILL.md`. Не выдумывай
  API, сверяй по KDoc версии. В прошлой заготовке `ToggleButtonDefaults.shapes()` не нашлось в
  `material3 1.5.0-rc01`; `ButtonDefaults.shapes()` нашлась.

## Лицензии и правила Telegram

- Итоговое приложение: GPL v2+ (Telegram). Исходники должны быть открыты. Inugram: MIT, файл `LICENSE` с
  уведомлением автора сохранять. См. `ATTRIBUTION.md`.
- Из MargyGram (GPL) код не копировать целиком: это клиент друга владельца, у владельца задача сделать свой.
  Идеи брать можно.
- Свои `api_id` и `api_hash` обязательны. Прочитай API Terms of Service Telegram (core.telegram.org/api/terms)
  перед публикацией. Не называй приложение «Telegram», не используй его логотип, не выдавай клиент за официальный.

## Секреты

`TG_APP_ID`, `TG_APP_HASH` только в Secrets репозитория. Не коммить, не печатать в логи (CI маскирует hash),
не передавать в аргументах команд.

## Как получать логи сборки

```
ID=$(gh run list --workflow=build.yml -L1 --json databaseId -q '.[0].databaseId')
gh run view $ID --log-failed > ~/log.txt
grep -nE "What went wrong|error:|FAILED|Error" -A 6 ~/log.txt | cut -c1-300 | head -60
```
Владелец присылает вывод; чини за один заход всё, что видно в логе.
